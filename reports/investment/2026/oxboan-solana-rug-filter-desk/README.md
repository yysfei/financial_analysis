# 0xboan 的 Solana meme 币筛查台（Rug Desk）

这份笔记评估 @0xboan 在 2026-10-17 发布的长文《Grok Bot from zero in one night: full setup + a copy-paste rug filter》，以及 2026-11-21 主页时间线里 @chenke20266 对该文和 @0xTenzo 视频的引用。这是 Solana meme 币的过滤与人工确认流程，方向性交易，**不是套利**。研究笔记不是交易指令，不运行交易，也不构成收益承诺。

## 结论

长文给出的骨架是清楚的：先用免费的公开接口做事实过滤，再让 Grok 搜索 X 上代码看不出的复制盘或协同发帖，最后由使用者自己签字买入；机器人不持有私钥。作者也写明这是他的设置而不是读者的策略，多数 meme 币会归零，过滤器「并不能让一个代币变好」，并且要求先纸面运行一周。

本轮核验后的要点如下。

- 文中出现的晚间报告和成交示例，配图自己就写着 “Paper run demonstration”“Illustrative data · not an actual run”“Example output · not an actual trade result”。例如标成 2026-10-17 的纸面晚间报告写 checked 240、realized pnl $593.00、DEMO_A +598.00 / DEMO_B −5.00，这些是示意，不是真实运行结果。
- 作者在文末写 “my github - github.com/0xboan”。本轮打开该 GitHub 用户页时，公开仓库数为 0、公开 gist 数为 0，因此不能把文章里的代码块当作已经可以克隆的公开实现。
- 文末同时给出 Telegram 邀请链接和 `fomo.family/r/0xboan`。这是推荐注册链接，属于利益冲突，不是过滤器有效的证据。
- 同一引用链上的 @0xTenzo 帖写有 “$105 → $17,679 BY 4 AM”。这是未经核验的业绩宣传，既没有钱包或成交账本，也不应回填成 @0xboan 长文的结果。本轮没有逐帧审看该视频。
- 因此：这套流程可以当作「先过滤、后人工签字」的研究脚手架，不能视为已验证交易系统。通用助手可以按文章搭建只读或纸面检查，不应持有钱包密钥，也不应自动买币。

## 逐步机制

公开文本把工作分成一晚能搭起来的文件和例行程序，主旨是：「code kills, Grok reads X, you sign。」

1. **准备**：Grok Bot、xAI API 密钥、Rugcheck 与 DexScreener 的公开读取，以及一只「今晚先不用」的 Solana 烧毁钱包。作者要求密钥写入机器上的文件，不要贴进聊天记录。
2. **漏斗**：先做免费检查，只有活下来的标的才花费一次带 X 搜索的 Grok 调用；再往后才涉及资金。配图漏斗依次是 LEAD、LIMITS、FACTS、POOL、JUDGE、FILL、WATCH、REPORT。被画成淘汰理由的例子包括 mint open、LP unlocked、thin pool、top 10 heavy、can't sell。
3. **事实层**：作者说 14 项检查里有 13 项是代码比较、不经过模型，第 14 项才让 Grok 读 X，用来抓换合约的仿盘、或大量新账户在同一分钟发同一句话这类接口不好表达的现象。正文强调要先去掉池子自身vault 和锁仓地址，再统计前十大持仓，否则几乎每个币都会像巨鲸币。
4. **资金限制与退出先于开仓**：`book.py` 在调用外部接口前先看当日亏损和开仓数量。退出规则在买入前写死，文中的例子是：流动性较入场抽走 40% 则全部退出；下跌 35% 退出；上涨 100% 先走一半；上涨 200% 再走四分之一；第一次减仓后，剩余部分在较峰值回撤 30% 时离开；6 小时仍没有 +20% 则退出。这些是作者自己的常数，文中写明「不是建议」，需要读者改写成自己的数字。
5. **票据规模**：`config.py` 里的数字是按 25 美元一笔票来调的。作者说多数人交易 meme 币是亏的，纸面成交价是屏幕价，真实成交不会更好，因此纸面结果只是上限不是预测。
6. **纸面一周再谈实盘**：`PAPER = True` 时，除了钱是假的，其余检查、报价和退出都按真的跑。若改为实盘，文章写的是：程序不再自己买，而是发出审批行，由使用者在自己的钱包里买 25 美元，再用一条命令把仓位登记进 `watch.py`。这与「机器人持有密钥自动下单」相反。
7. **机器人说明**：配图中的 Bot 职责写明：每个代币都必须经过 `check.py`；「You never buy, sell, sign or move funds」；未经聊天里明确要求不得放宽 `config.py` 过滤器；来源宕机时要说出是哪一个并跳过，不得猜测缺失数字。

正文里还有若干代码块和完整的 14 项阈值表，在 `article.plain_text` 中是空缺或插图位置。本轮阅读了漏斗图、纸面示例和建 Bot 说明，但没有把每一张代码截图逐行转录进本报告。因此，下面不把未转录的阈值写成已核对参数。

## 收益口径与成本

没有已验证收益可以列表。

示意报告里的 593 美元已实现盈亏，来自被标明为非真实运行的 DEMO 数字，不得写入成绩。25 美元票据、每日最多扫描约 240 个新币、以及「只有活过 13 项检查的标的才调用 Grok」都是成本结构说明。作者说 Grok 费用随「存活者」而不是随扫描量增长；本轮没有他的实际账单。

即便过滤器减少了一部分「一眼假」的归零币，剩余买入仍然完全暴露在方向、流动性和合约风险里。纸面成交用屏幕价，作者已经提醒这是上限。

## 风险

- **标的本身**：Solana meme 币大量归零、被撤池、无法卖出。过滤器只能去掉部分明显缺陷，不能产生正期望。
- **过滤器失效**：规则公开后可被针对；持仓分布、锁仓和流动性可以伪装；X 上的舆情也可被刷。第 14 项依赖模型读 X，存在幻觉和漏判。
- **执行与滑点**：即便人工签字，薄池里的 25 美元也可能明显差于屏幕价；退出规则在流动性已经抽走 40% 时未必能按设想成交。
- **密钥与钱包**：文章的正确边界是机器人不持有私钥。若使用者为了「全自动」而把私钥或可转账权限交给助手或脚本，风险性质就变了。
- **利益冲突**：FOMO 推荐链接和电报群是推广通道。仓库中其他 FOMO 相关宣传已另案记录，不在这里合并收益。
- **关联宣传**：@0xTenzo 的过夜倍数与长文里谨慎的纸面口径不是同一证据等级，不能互相背书。

## 可执行性与自动化部署评估

只做研究、不下单、不连接钱包。

- **开发难度（估计，不是工期承诺）**：若公开代码可复用，把只读检查接到 Rugcheck / DexScreener 并做纸面日志，对熟悉这些接口的人大约是一两天到一周。本轮找不到公开仓库，就需要按文章自己重写，工作量更大，而且必须承认阈值可能与作者原版不同。
- **数据与 API**：Rugcheck、DexScreener 的公开读取和 xAI 的付费调用在文章中是核心依赖。接口变更、限流或字段定义变化都会让过滤器失效。本轮未做接口连通实测。
- **确定性自动交易**：作者自己的目标态也不是自动买币，而是审批后人工签字。即使如此，也不应在没有纸面日志和独立复核前进入实盘。自动把过滤器结果变成市价买单，尤其不适合。
- **通用 AI 助手的边界**：可以帮着整理检查清单、在纸面模式下读公开接口并写下淘汰理由。不可以：保管或使用钱包密钥、代为签字、连接钱包、把示意报告当成业绩、或为了「找到可买的币」而放宽过滤器。
- **与本仓库其他报告的关系**：这不是 Polymarket 五分钟市场，也不是已归档的 FOMO 套利宣传。引用链出现在同一条时间线里，不表示策略相同。
