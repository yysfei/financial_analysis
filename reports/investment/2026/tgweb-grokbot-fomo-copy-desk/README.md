## 结论

[@TGweb3333](https://x.com/TGweb3333/status/2125031652699029721) 把一套材料宣传成油管上价值 4,000 美元的交易课程，并称已整理成「最完整的 Grok Bot 交易提示词」，共十页，可以自动生成五个交易机器人，通宵盯盘。4,000 美元和「一手内部信号」本轮没有核到来源，记为 C/D。

OCR 读到的主线是：让 Grok Bot 在用户自己的电脑上建一个私人跟单台。五个角色是 Watcher、Vetter、Sizer、Executor、Guard，加上一个 iPhone 网页和推送。执行方式是通过屏幕上的 Chrome 去点 FOMO 网页的 Buy / Sell。用户自己登录。提示词写明不要密码、助记词、私钥或 2FA，也不要点 Withdraw。

同一份材料写到 FOMO 没有公开交易 API，并提到非官方 app API 主机 `https://prod-api.fomo.family`，以及从 Chrome 调试端口读取会过期的 Bearer 会话令牌，限定为读取和核对。这是非官方接口，可能随时失效，而且会话令牌和条款风险都很高。**本笔记不写如何读取令牌，不写调试端口的用法，也不写如何调用该接口。**

默认状态是 PAPER。材料里的 100 美元现金是示例，不是实盘成绩，等级 E。LIVE 需要用户输入确认。提现只按用户命令，由用户自己确认并完成 2FA。

这是一套可讨论的跟单工程草图，不是已验证盈利系统。没有公开实盘，没有可核对钱包。标的是 Meme 和链上交易，方向和尾部风险都很大。不应让 Grok Bot 无人值守下单，不应连接钱包，也不应实现绕过条款或套取令牌的步骤。

## 策略类型与适用环境

- 属于：按他人成交做跟单的研究流程。提示词把筛选、核对、仓位、执行和风控拆成五个角色，并要求先纸面。
- 适用环境（按提示词，尚未验证）：FOMO 页面可以人工登录；鲸名单的筛选条件有稳定数据；纸面对账能在下单前完成；用户在每一笔 LIVE 和每一次提现前亲自确认。这些条件没有被一份公开账单证明。
- 不属于：无风险套利、已审计的交易 API 接入，也不是可以通宵无人值守的系统。标题里的「通宵替你盯盘」和正文里的人工确认是两套要求。

## 提示词中的规则（OCR）

下面全部来自十张图的 OCR，个别词可能识别错误。这里只归档规则含义，不提供实现。

鲸名单：每晚读取 24 小时、7 日和 30 日排行榜。名字要出现在三个窗口里的至少两个。胜率不低于 55%。7 日至少 20 笔。持仓时间的中位数不低于 15 分钟。单一币种不超过 7 日盈亏的 40%。按 7 日盈亏乘以胜率排序，取前 25。

Whale proof：三个鲸最近五笔 FOMO 成交，要在 60 秒内对上链上签名。匹配率低于 80% 则停止，并且不得进入 PAPER 夜盘。

执行边界：默认 PAPER。LIVE 要用户输入确认。不要密码、助记词、私钥或 2FA。不要点 Withdraw。提现只在用户发出命令后，由用户自己确认。

这些阈值没有公开样本，也没有失败日。OCR 若把不等号或窗口认错，阈值会变。在看到原图逐字校对之前，不能把 55%、20 笔、15 分钟、40%、前 25、60 秒和 80% 写成已经冻结的参数。

## 盈利来源与成立条件

若这套跟单成立，盈利来自被跟踪地址的后续成交仍然有正期望，并且跟单延迟、费用和失败单没有把期望吃掉。成立条件还包括：排行榜不是被刷出来的，链上签名和站内成交指的是同一笔，纸面阶段真的会在匹配率不足时停掉，以及 LIVE 不会在用户没有确认时发出。

本轮没有地址、没有成交哈希、没有纸面日志。100 美元只是示例。因此没有任何收益口径可以写成实盘。

## 风险

- 标的风险：Meme 和链上交易可以在短时间内接近归零，跟单会放大尾部。
- 数据风险：排行榜可以被交易刷出来。三个时间窗和 55% 胜率没有独立检验。
- 对账风险：站内成交和链上签名对不上时，提示词要求停止。做不到这一点，纸面结果就没有意义。
- 接口与令牌风险：非官方 API 和浏览器会话令牌可能失效，也可能违反网站条款。读取他人或自己的会话令牌来驱动交易，还有账户被接管的风险。本笔记不提供提取或调用步骤。
- 自动化范围蔓延：屏幕点击 Buy / Sell 一旦离开纸面，就不再是研究笔记。提示词把 LIVE 和提现写成必须由人确认，这个边界应当保留。
- 识别误差：整份规则来自 OCR，阈值可能认错。

## 本金、期限与专业知识

- 本金：示例 100 美元，不是建议仓位，也不是成绩。
- 期限：材料写每晚更新鲸名单，并提到夜盘纸面。没有持有期公式，筛选条件里只有持仓中位数不低于 15 分钟这一条。
- 专业知识：需要能读链上签名、区分纸面和实盘，并理解 Meme 的流动性。提示词没有给出已审计的实现。

## 可执行性与自动化部署评估

- 开发难度：五个角色、网页和推送，作为软件草图可以讨论。要成为可核验系统，需要稳定的只读数据、失败样本、人工确认和与条款相符的接口。材料自己写出 FOMO 没有公开交易 API。非官方主机和会话令牌使这条路径不确定，而且本仓库不实现它。
- 能否确定性自动化：不能。令牌会过期，非官方接口可能失效，匹配率低于阈值时材料要求停机，Meme 价格也不能由这些阈值确定性推出。
- AI / Grok Bot 的边界：可以在有人监督时整理已经公开的规则并标出证据缺口。不能无人值守点击 Buy / Sell，不能连接钱包，不能保存助记词、私钥、密码或 2FA，不能从浏览器调试端口取出会话令牌，不能调用非官方交易接口，不能点 Withdraw。
- 不适合自动化的原因：没有可核对业绩，执行依赖可能违规的会话，标的尾部风险大，而且 LIVE 被写成必须由人确认。屏幕点击一旦无人值守，就超出了研究范围。

停止条件：要求提供令牌提取或非官方下单步骤；要求把 100 美元示例写成实盘；要求把 4,000 美元课程写成已核来源；要求通宵自动交易。出现这些情况就停在只读。
