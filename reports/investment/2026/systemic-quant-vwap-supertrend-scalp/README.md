## 逐步机制

按 `indicator_v1.pine` 的默认参数，信号逻辑可以拆成下面几步。

1. **VWAP。** 用 `hlc3 * volume` 累加后除以成交量，得到锚定 VWAP。锚点可选 Session、Week、Month，默认 Session。Session 重置条件是 `ta.change(time("D")) != 0`，也就是图表品种时区里的日历日切换，不是另外写死的美股常规交易时段。
2. **高周期 Supertrend。** 在 `request.security` 中调用 `ta.supertrend(atr_multiplier, atr_period)`，默认 ATR 周期 10、乘数 3.0、周期 15 分钟，并且 `lookahead=barmerge.lookahead_off`。包装函数返回的是 Supertrend 的上一根值 `[st_line[1], st_dir[1]]`，因此用的是已经结束的高周期柱，而不是仍在形成的当前 15 分钟柱。方向判定为：`htf_direction < 0` 视为多头，`htf_direction > 0` 视为空头，这与 TradingView `ta.supertrend` 的常用方向约定一致。这样做可以降低高周期指标在未收盘时改写的风险，但也会增加一档高周期滞后。
3. **质量过滤。** 相对成交量是当前成交量除以 20 周期成交量均线，默认要求 `>= 1.2`。实体占比是 `abs(close-open) / (high-low)`，默认要求 `>= 50%`。源码里还有时间线帖未写明的方向过滤：做多要求收阳（`close > open`），做空要求收阴（`close < open`）。
4. **原始条件。** 做多：收盘高于 VWAP，且高周期 Supertrend 为多，且成交量、实体和收阳条件都通过。做空则镜像。收盘恰好等于 VWAP 时，既不满足高于也不满足低于。
5. **状态机与每日上限。** 只有当当前状态还不是同向（例如尚未处于 `BULLISH`）且当日计数未达到上限时，才把一次原始条件写成正式信号，并把计数加一。买卖共用同一个每日上限，默认 3 次。新的日历日只会把 `session_signal_count` 归零，**不会**重置 `current_trend_state`。若前一日以 `BULLISH` 结束，次日开盘后在状态被改写前，不会再次发出做多标签。
6. **标签与告警。** `plotshape` 和 `alertcondition` 都要求 `barstate.isconfirmed`。脚本没有止损、止盈、移动退出、仓位或订单类型。HUD 显示的状态是 `BULLISH READY`、`BEARISH READY`、`WAITING ALIGNMENT` 或 `LIMIT REACHED`。仓库 README 末尾的操作提示写的是 HUD 出现 `FULL ALIGNMENT` 时迅速执行，但源码并不显示这一字符串。

关于「不重绘」：高周期引用使用了 `lookahead_off` 和上一根高周期值，历史图上的高周期线因此相对稳定。但状态变量和每日计数的更新**没有**放在 `barstate.isconfirmed` 里，只有标签和告警有这个限制。实时未收盘的柱如果一度满足原始条件，可能先改写状态并占用当日次数，随后在收盘时不再画出标签或发出告警。历史回放通常一根柱计算一次，和实时逐笔更新不必相同。因此，不能把 README 里的「100% fixed and historical-backtest accurate」理解成已经完成、且与实时告警完全一致的绩效回测。本轮没有在 TradingView 里实盘或回放核验这一点，以上只是对源码控制流的阅读结论。

## 风险

- **方向与模型风险：** 这是趋势过滤后的方向性进场，不是对锁。VWAP 附近震荡、高周期 Supertrend 滞后或盘中假突破，都会导致连续亏损。过滤条件减少信号，不等于提高期望值。
- **规则不完整：** 没有出场、止损、加仓/减仓和仓位公式。即使标签判断正确，如何退出仍完全交给使用者。
- **实现与实时一致性风险：** 每日状态在未确认柱上就可能被改写；次日不重置趋势状态；文档中的四条条件少于源码中的五条；HUD 文案与 README 提示也不完全一致。
- **成本与流动性风险：** 短周期交易对费用和滑点非常敏感。低流动性品种或消息时段，标签出现时的可成交价格不必等于收盘价。
- **平台与合规风险：** 脚本可加到任意品种，但不构成在某地可合法交易该品种的说明。仓库另有 Telegram 引流，后续「高级脚本」不在本次核验范围。
- **尾部风险：** 没有日亏损限额或强制平仓。次数上限只限制新信号条数，不限制单笔亏损大小。

## 可执行性与自动化部署评估

对人工交易者，把这段 Pine 脚本复制到 TradingView 并打开告警，技术门槛不高。要把它变成可重复执行的方法，还需要自己补上品种、时段、订单类型、仓位、出场和成本记录。这些内容公开材料都没有给全，所以可执行性只能评为：**可以复现进场过滤，不能复现完整交易系统。**

对专用自动化：源码已提供 `alertcondition`，可以把 TradingView 告警接到 webhook，或把同样规则改写成自己的行情程序。开发工作量中等，主要难点不在复现四个公开过滤器，而在处理未收盘柱、会话时区、成交与标签不一致，以及补写出场和风控。即便做成程序，也仍然没有公开的正期望证据。

对通用 AI 助手或本 Bot：可以继续做只读核验、规则对照和归档，但不应连接券商或钱包、不应自动下单，也不应把告警直接转成实盘委托。缺少出场规则和成本模型时，所谓「确定性自动化」并不成立。

所需专业知识包括：VWAP 与 Supertrend 的含义、图表时区与 `time("D")` 的会话边界、短线交易成本，以及 Pine 在历史计算和实时计算上的差别。本金和持有期未知；按作者设定，这是分钟级日内操作，不是长期配置。
