## 结论

[@0xcherry](https://x.com/0xcherry/status/2124774608670998543) 只说自己用刚发布的 GLM-5.4 跑了 AutoQuant bench，思考更长，执行前会先探索，并请别人自己跑，跑完再点评。帖文没有说这是已经验证的实盘系统，也没有给出自己的收益。

打开的仓库是 https://github.com/TraderAlice/Auto-Quant 。它公开，默认分支是 `master`，不是 `main`。`main` 上的 README 会 404。创建于 2026-04-22。该次读取的 `pushed_at` 是 2026-11-23T07:10:50Z（北京时间 15:10:50），stargazers_count 396，forks_count 51。

官方 README 把 Karpathy 的 autoresearch 模式用到 FreqTrade 上。成功标准写的是：循环能跑出可解释的 `results.tsv`，不是找到可盈利策略。README 还有一句：Nothing in this repo is a recommendation to trade real capital。

因此这是一个受监督的研究工具。它可以用来读规则、看一次循环留下什么表。它不是已经证明能赚钱的交易系统，也不应交给自动实盘。2026-11-24 追加的模型对比包见文末。它不改变上面的成功标准，也不把页面上的 Robust Sharpe 写成实盘盈利。

## 风险

- 研究与交易的距离：循环能写出 `results.tsv`，只说明流程跑完。表上的正数可以来自过拟合、标签泄漏或成本没算全。
- 自述分数：Sharpe 18 已经被仓库自己否定。保留下来的分数仍是自述。
- 宇宙集中：五个加密资产、三种周期。相关性高时，多品种不等于分散。
- 执行：从研究表到实盘还要交易所权限、仓位和故障处理。仓库声明这不是实盘建议。
- 模型宣传：帖文对 GLM-5.4 的描述没有附运行日志。换一个模型或一次运行，不能自动提高分数的可信度。
- 默认分支：材料在 `master`。对着 `main` 找 README 会 404，不能据此说仓库不存在。
