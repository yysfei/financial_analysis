## 结论

提示词作为开发需求清单有用。专用交易程序在合法支持的 API 上，技术上可以开发。这不是现成策略，更不是“转发之后就会自动盈利”。年利 12%、完全放置，以及“AI 造出了同款 EA”，都没有被独立验证。

四个可执行性要点：

1. 两张图仍有占位符。候选策略从趋势一直列到资金费基差，没有可以直接交易的入场、退出、标的和统计优势。
2. 作者引用的 EA 长文只展示历史回测摘要。规则、完整日期、参数、费用和交易明细都没有公开，不能把这份 MetaTrader EA 和中文 Python / CCXT 提示词当成同一个程序。
3. 若按“5 年”叙述假设截图覆盖整整 5 年且没有追加资金，3,000 本金和 1,121.30 净利润对应累计 37.38%、复合年化约 6.56%，不是 12%。这是条件算术上的口径差异，还不能断定造假或断定截图的实际周期。
4. “每一仓都要交易所有原生止损”不是任意交易所、现货或合约都能实现。Freqtrade 的支持矩阵列出多种不支持的组合。不符合要求就应拒绝，不能在运行时默默降级。

本案例和 [xmglia / FOMO](../xmglia-fomo-ai-arbitrage-claims/README.md) 都讨论专用程序与通用助手的边界，但业绩和执行平台不同。它也不是已归档的 Polymarket 强化学习案例。

## 策略类型与逐步机制

这张图是如何组织量化研发的清单，不是一个唯一策略。

- 趋势、反转、突破和模型信号是方向性预测，不是套利。
- 做市和微结构可能赚点差，但有逆向选择、库存和排队风险。
- 现货加永续的资金费或期限基差，必须处理对冲数量、保证金、借贷、资金费变化和两腿成交。它不是天然锁定的收益。
- 跨资产配对里的相关或协整可以失效。统计套利不等于确定套利。
- 未公开的 EA 连上面哪一类都没有披露。“不补仓”是风险特征，不是盈利机制。

合理顺序是：选定一个产品和一种策略，取得授权数据，定义不含未来信息的规则，按时间顺序回测并冻结，做前瞻纸面，完成独立风控和执行验收，然后才另行考虑小额实盘。不能先让模型筛几十种策略、挑历史最好的一种，再把同一段历史称为验证。

### 年利 12% 与截图的条件算术

只在截图代表连续整 5 年、没有中途净注资、3,000 是全部初始资本、1,121.30 是该期间全部净收益时：

```text
期末权益 = 3000 + 1121.30 = 4121.30
累计回报 = 1121.30 / 3000 = 37.37666667%
复合年化 = (4121.30 / 3000) ^ (1/5) − 1 = 6.55714966%
简单年均 = 1121.30 / 3000 / 5 = 7.47533333%
每笔 trade 的报表净收益 = 1121.30 / 1626 = 0.68960640 账户货币
```

因此“5 年 + 这张图 + 年利 12%”还不能互相印证。测试区间、仓位或计息口径、宣传所指的版本，都可能不同。需要完整报告之后再判断，不先给欺诈定性。

若额外遗漏的双边总成本平均超过约 0.69 / 笔 trade，就足以抹去这份回测的总净利。这里说的是尚未计入的额外成本，不是把已经包含的佣金再扣一次。现有资料不能确认到底遗漏了多少。

## 资金门槛

没有真实最低本金、合约乘数、最小下单、维持保证金、强平、杠杆和各策略敞口。截图里的 3,000 只是回测初始值，不是平台最低入金建议。

“每笔 1% 风险”不是“下 1% 本金的仓位”。在止损能够及时成交的简化假设下：

```text
Q × 单位止损价差 + 未含费用和滑点预算 ≤ 风险预算
```

真实跳空可以超过预算。相关持仓应合并风险。2 倍杠杆不保证安全。跨场所的双边库存和备用保证金可能明显增加占用，不能用屏幕收益除以单边保证金来夸大回报。

## 技术架构与执行可行性

### 两条路线分开

1. **Python / 交易所。** Python 策略，加上 Freqtrade 或适用的专用引擎、CCXT 或官方 API、独立订单状态机、组合风控、数据库和告警。它适合受支持的场所和节奏，不代表所有 CCXT 市场、资金费策略或低延迟微结构都能由 Freqtrade 原样支持。快速向量化筛选和最终事件驱动回测的成交假设应当一致，不能挑最乐观的结果。
2. **MetaTrader EA。** 需要 MQL5 和具体终端、经纪商的品种规格与手续费、Strategy Tester 配置。如果只有封闭的 `.ex5` 而没有源码，仍要检查权限、网络访问、版本和可重复性。不能把 CCXT 脚本称作已经复现了原 EA，也不能未经检查就运行 LINE 分发的软件。

| 部分 | 工程难度 | 实盘前要求 |
| --- | --- | --- |
| 搭目录、单策略回测和只读采集 | 低到中 | Python、固定依赖、数据校验和单元测试。演示不是盈利证据 |
| 历史清洗、滚动样本外和成本模型 | 中到高 | 退市和幸存者偏差、时间戳、拆分和资金费、数据版本、参数搜索次数 |
| 标准单场所、非高频执行 | 中到高 | 产品支持、沙盒与实盘差异、部分成交、幂等、精度和撤单竞态 |
| 跨场所对冲、微结构和多引擎 | 高 | 时钟、库存、队列位置、腿风险、事件回放、限流和网络 |
| 运维和风控 | 高，并且持续 | 告警、值守、独立熔断、真实余额和仓位对账、密钥与升级审计 |

[Freqtrade 文档](https://www.freqtrade.io/en/stable/) 当前支持回测、dry-run、live，以及 Telegram 和 WebUI，并提示需要基础 Python 和交易知识。通用基线大约是 2 vCPU、2 GB 内存和 1 GB 磁盘，推荐 Docker。这个基线不是本图多模型、全市场研究和高频执行的容量认证，也不包括长期行情存储、回测搜索和容灾。没有规格就不能给出固定工期或费用，更不能保证一分钟或两天可以验收生产系统。

### 原生止损是硬验收项

[Freqtrade 止损文档](https://www.freqtrade.io/en/stable/stoploss/) 的支持表显示，不同场所和产品并不相同。例如 Binance 现货在该表中是 limit 类型；Bybit 现货和 Hyperliquid 现货不支持该框架的交易所止损。现货支持不能直接迁移到合约。止损限价太紧可能不成交，stop-market 则可能滑点很大。默认 maker 不会确保每一笔都按 maker 收费。穿价单可能变成 taker，挂单也可能长期不成交。

如果需求是“每仓必须有交易所止损”，启动时就要校验真实支持，以及保护单是否成功挂出。不支持或挂出失败，就拒绝新开仓。已有仓位如何安全处理，必须预先设计、告警并经过审批，不能在运行时让模型临时撤掉保护。reduce-only 也要按该产品的 API 语义检验，不能假定所有现货 API 都有这个参数。

### 专用程序与通用助手的边界

- **可以做成专用自动化的：** 固定规则的采集、信号计算、纸面撮合、风险限额校验、受支持 API 的下单和账本记录。这需要专用进程和可审计软件，不是聊天会话本身。
- **通用 AI 助手适合做的：** 整理规格、解释官方文档、生成待审查的代码和测试、离线研究、发现异常和准备审计。输出、引用和置信度都要再校验。
- **不能保证的：** 自行发现长期优势、准确回测、没有幻觉的调参、全天毫秒级执行、永不宕机和稳定收益。不要让模型直接修改硬风控，也不要在夜间自动把“回测更好的版本”升到生产。
- **本次没有做的：** 创建交易程序、例程、调度或部署，连接 API，索要密钥，下单。研究要求不是实盘授权。以后真正交易仍需平台允许的能力、明确授权，以及单独的风险和合规验收。

[Grok Bot 指南](https://x.ai/bot/guides/grok-bot-101) 说明云电脑和工具协调。它不证明交易写权限、确定时延或收益。

## 风险

反复回测、删掉“历史表现差”的市场环境，会把环境过滤器也过拟合。过滤规则必须先冻结，再看从未用于筛选的数据。walk-forward 同样会被反复挑选窗口污染。每年 50 笔或纸面 30 笔，不是显著性和稳健性的充分条件。

未来函数包括：先看到收盘再用收盘价成交、用全样本做归一化、后复权错位、使用未完成的多周期 K 线，以及使用未来事件日程。Freqtrade 的 lookahead-analysis 有用，但官方说明它只检查执行到的信号，可能漏检或误判，不能当成没有未来函数的证书。

点差、动态佣金、隔夜费和资金费、跳空、强平、重复订单、网络中断、交易所维护、时钟和夏令时、陈旧行情、未平仓估值，都会拉开回测和实盘。1%、3% 和 15% 是控制目标，不是损失上限。

禁止提现的 API 不是零风险，错误交易仍然可以亏损。最小权限、IP 白名单、纸面与实盘分离、隔离签名和依赖审计都不能省。地区、经纪商、衍生品资格、接口条款和数据授权需要另核。对外代客或收费可能涉及额外义务。未知的 LINE 分发物没有获取，也没有运行；“免费”不免除供应链风险。

## 验证方案与停止条件

### 补全证据，不接交易权限

取得规则或可审计源码、版本、完整 HTML 或 CSV、参数、日期、产品、经纪商、点差、佣金、隔夜费、tick 模式、延迟和逐笔数据。标题 12% 要和截图的期间、计息、净注资、版本对上。对不上，就不能引用为预期回报。一次只选一个明确策略和市场，以及一个合法 API，不要同时堆上图里的全部策略。

### 可复现回放

按时间切分，保留从未用来选择参数的最终测试段，并披露试过多少版本。清洗和信号都不得使用未来。用历史费用和保守执行假设重算，再加大成本和延迟。检查盈利是否依赖少数行情或少数大单。对账净利、Profit Factor、两种回撤和每笔收益。用独立计算复核报表，不只保存图。

### 只读前瞻和故障注入

记录冻结之后的全部信号、报价和纸面成交，包括未成交、拒单、撤单和错过的机会。验证断流、重复和乱序、交易所超时但实际已成交、重启恢复、止损失败和时区切换。风控进程与模型进程分开。30 笔只是流程检查的门槛之一，不因为满 7 天就自动通过。

### 停止条件

没有完整证据、不支持必需止损、无法复现、未来函数没有排除、费用压力后没有优势、依赖大规模寻优、纸面与模型的偏离无法解释、必须绕过平台条款或交出高权限密钥，都停止实盘升级。可以继续学习和模拟。无法证明盈利，不等于已经证明永远无效。

## 符号关系

```text
CAGR = (期末权益 / 期初权益) ^ (1 / 年数) − 1
```

它只适用于没有中途外部现金流的简化情形。有现金流时，要区分时间加权和资金加权，不能拿标题或一次净利直接年化。纸面成交不等于真实可成交。代码能运行，也不等于策略有正期望。
